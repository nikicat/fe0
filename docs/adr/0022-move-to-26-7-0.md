# 22. Move to Fe 26.7.0

- Date: 2026-11-19
- Status: accepted; supersedes the toolchain version of [0015](0015-move-to-26-6-0.md)

## Context
[0015](0015-move-to-26-6-0.md) moved to Fe 26.6.0 and allowed no other upgrade in the window
unless a blocking bug needed it. Fe 26.7.0 came out on Nov 18. Two of its changes remove work
that we would otherwise have had to do before the submission:
- **It passes one-scalar constants as values** (argotorg/fe#1978, fixing #1964). Fe 26.6.0
  copied a function once for each struct constant passed to it. With no change to our code,
  the runtime code of the phase contracts at `-O s` (Nov 19) shrinks:

  | Contract | 26.6.0 | 26.7.0 |
  |---|---|---|
  | Lexer | 6,031 | 5,785 |
  | Parser | 22,578 | 17,063 |
  | Checker | 22,452 | 21,312 |
  | Back | 17,857 | 17,231 |
  | Compiler | 1,893 | 1,653 |

  The Parser had 1,998 bytes left under the 24,576-byte limit, and now has 7,513 (task
  Ts3ty7). Compiling `corpus/amm.fe` on chain costs 29,054,210 gas, down from 29,586,106.
- **It builds native code on AArch64 Linux** (argotorg/fe#1989, our PR). On 26.6.0, native
  builds and native tests on an arm64 host needed Fe built from a branch of our fork.

Every suite passed on 26.7.0 after one change to Fe0: it now rejects a field listed twice in a
`uses`, as Fe 26.7.0 does (argotorg/fe#1987). [0001](0001-strict-subset.md) records it (update
of Nov 19).

## Decision
Build, test and submit on Fe 26.7.0, as the dev container pins it. We don't upgrade again in
the window unless a blocking bug needs it.

## Alternatives
- **Stay on 26.6.0:** the rules would not change. But the Parser would keep only 2 KB of room
  for the syntax that SPEC.md §10 marks as missing or narrower than Fe, and native builds on
  arm64 hosts would still need a patched Fe.

## Consequences
- Native builds and native tests on an arm64 host use the release binary. Our fork's branch is
  no longer needed (task T56pax).
- The submission README (T0010) will explain the upgrade.
