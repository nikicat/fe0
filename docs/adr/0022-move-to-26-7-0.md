# 22. Move to Fe 26.7.0

- Date: 2026-11-19
- Status: accepted; supersedes the toolchain version of [0015](0015-move-to-26-6-0.md)

## Context
The toolchain may change in the window only for a good reason, since every change risks the
build. Fe 26.7.0 fixes no blocking bug, but two of its changes remove work that the submission
would otherwise need:
- **It passes one-scalar constants as values** (argotorg/fe#1978, fixing #1964). Fe 26.6.0
  copies a function once for each struct constant passed to it, and Fe0 passes `Spelling`
  constants in many places. On 26.7.0 every phase contract is smaller with no change to Fe0's
  code, and the Parser has about 7.5 KB of room under the 24,576-byte limit (DESIGN.md §8).
- **It builds native code on AArch64 Linux** (argotorg/fe#1989, our PR). On 26.6.0, native
  builds and native tests on an arm64 host need Fe built from a branch of our fork.

## Decision
Build, test and submit on Fe 26.7.0, as the dev container pins it. We don't upgrade again in
the window unless a blocking bug needs it.

## Alternatives
- **Stay on 26.6.0:** the rules would not change. But the Parser has only 2 KB of room on 26.6.0
  (`-O s`) for the syntax that SPEC.md §10 marks as missing or narrower than Fe, and native
  builds on arm64 hosts would need a patched Fe.

## Consequences
- Fe0 rejects a field listed twice in a `uses`, as Fe 26.7.0 does (argotorg/fe#1987,
  [0001](0001-strict-subset.md)).
- Native builds and native tests on an arm64 host use the release binary. Our fork's branch is
  not needed (task T56pax).
- The submission README (T0010) explains the toolchain.
