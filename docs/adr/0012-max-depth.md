# 12. The parser caps nesting at `MAX_DEPTH` = 20

- Date: 2026-11-04
- Status: accepted

## Context
The parser is recursive descent, and Fe keeps return addresses on the 1,024-slot EVM stack, so
recursion is bounded by the stack, not by gas: at most 1,019 nested calls for a one-argument
function (`spike-limits/`). Measured with the real parser on Fe 26.5.1: at `-O 0`, 20 nested
parentheses parse and 22 overflow, about 45 stack slots per parenthesis. 12 nested blocks
parse. At `-O 2`, every probe up to 28 parentheses parsed.

## Decision
`MAX_DEPTH` is 20 depth steps, and deeper input is rejected with `P_TOO_DEEP`. A function body
and its outer expression take 2 steps, each parenthesis 1, and each block inside a block 2. So
18 nested parentheses or 9 nested blocks are allowed, which keeps a margin at `-O 0`.
`parser_tests::deepest_nesting` checks both.

## Alternatives
- **A higher cap for optimized builds only:** the tests run at `-O 0` too, and one limit is
  simpler to specify.
- **An explicit stack instead of recursion:** removes the limit, at the cost of a parser that
  no longer reads like the grammar.

## Consequences
- This limits only the compiler. Code generated by Fe0 keeps frames in memory
  ([0007](0007-codegen-from-ast.md)).
